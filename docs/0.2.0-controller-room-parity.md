# Archipelago Controller 0.2.0 — Controller Room Parity

This document is the implementation specification and acceptance checklist for Controller-hosted rooms. A Controller room must expose the same provider-neutral room model used by official Archipelago rooms, while never publishing passwords, local paths, saves, server configuration, raw multidata, unchecked placements, or future sphere information.

## API contract

Controller API v2 is available alongside the v1 API used by 0.1.x clients.

- `GET /api/controller/v2/schema`
- `GET /api/controller/v2/room/<id>/status`
- `GET /api/controller/v2/room/<id>/snapshot`
- `GET /api/controller/v2/room/<id>/dashboard`
- `GET /api/controller/v2/room/<id>/spheres`
- `GET /api/controller/v2/room/<id>/slots/<slot>/files`
- `GET /api/controller/v2/room/<id>/files/<file-id>`
- `GET /api/controller/v2/room/<id>/trackers`
- `POST /api/controller/v2/room/<id>/actions/wake`
- `GET /api/controller/v2/host/room/<id>/export`

Public responses contain `original` sanitized observations and `enriched` resolved room data, an API/schema version, generation identity, source revisions, ISO timestamps, stale state, and provider capabilities. Safe public GET routes support CORS, ETags, and conditional requests. Desktop clients negotiate v2 first and visibly fall back to v1.

The host export requires a 256-bit bearer key stored with Electron `safeStorage`, is loopback-only unless remote access is explicitly enabled, supports bounded section selection, and redacts secrets and machine-local information. Spoiler fields additionally require host opt-in, `includeSpoilers=true`, and a non-race seed.

The always-on room broker is separate from an actively shared room portal and exposes every API-visible saved room while Controller runs:

- `GET /api/controller/v2/rooms`
- `GET /api/controller/v2/rooms/<managed-id>/snapshot`
- `GET /api/controller/v2/rooms/<managed-id>/dashboard`
- `GET /api/controller/v2/rooms/<managed-id>/hints`
- `GET /api/controller/v2/rooms/<managed-id>/activity`
- `GET /api/controller/v2/rooms/<managed-id>/spheres`
- authenticated `POST` actions for refresh and wake

It binds to `127.0.0.1:38283` by default, normalizes official, local, and remote Controller providers, and serves its OpenAPI contract from `/api/controller/v2/openapi.yaml`.

## Room experience

- [x] Progress, Hints, Activity, Spheres, and Downloads appear in both desktop Rooms and the hosted page.
- [x] Official and Controller providers normalize to the same player, hint, activity, sphere, and file models.
- [x] Tables support sorting and slot/status filters and show room totals and stale-data warnings.
- [x] Online rooms refresh every five seconds; offline rooms every fifteen seconds with bounded backoff.
- [x] The last successful sanitized snapshot survives a restart.
- [x] Every remote file can be selected, downloaded, redownloaded, or downloaded as a batch with progress and cancellation.
- [x] Downloads use bounded `.part` files and atomic completion; immutable originals are never endpoint-patched in place.
- [x] Password required state is imported, while room passwords remain encrypted locally.

## Tracking and spheres

- [x] The tracker sidecar publishes checked location IDs and resolved data-package names.
- [x] Static spheres are decoded once per artifact SHA-256 using bounded, non-executing decoding.
- [x] Unknown globals/reducers, unsafe archives, excessive nesting/collections, and unsupported formats are rejected.
- [x] Public spheres contain checked locations only and report finder and receiver independently.
- [x] Precise unavailable reasons are returned for absent, old, malformed, or incompatible sphere data.
- [x] Universal Tracker analysis has an always-available Recalculate action, cancellation, fingerprints, stale detection, and last-good-result preservation.
- [x] Host-owned analyses persist in the room workspace; guest analyses remain guest-local and persist in their saved room.

## Tool installation

- [x] Missing Universal Tracker (`tracker`) and SlotLock (`slotlock`) show installation cards.
- [x] Installation uses the APWorld Manager's compatible indexed release, checksum verification, archive inspection, staged replacement, rollback, warning, and process lock.
- [x] Inventory and launcher components refresh without restarting Controller.
- [x] Browser buttons use allowlisted `archipelago-controller://install-apworld?worldId=...` links, with the catalog repository as browser fallback.

## Remote wake

- [x] Wake is disabled per room by default and cannot stop or replace another active room.
- [x] Wake uses JSON, validated Origin, a sharing-session CSRF nonce, per-IP/room throttling, one active attempt, and cooldown.
- [x] Statuses are `disabled`, `starting`, `online`, `busy`, `failed`, and `host unavailable`.
- [x] Remote stop/restart/admin and wake while Controller is closed remain unavailable.

## Security and compatibility acceptance

- [x] v1 remains functional for 0.1.x guests; v2 guests show “Limited 0.1 host” when falling back.
- [x] Future unsupported API versions fail explicitly.
- [ ] Public and host schemas, CORS, ETags, redaction, race-mode rules, and size limits have automated tests.
- [x] No public response includes secrets, login commands, paths, saves, multidata, unchecked placements, or future spheres.
- [ ] Modern, legacy, malformed, truncated, oversized, and hostile multidata fixtures never execute code.
- [ ] Two-Controller LAN/internet smoke tests and official-room regression tests pass.
- [ ] Installer and portable artifacts are published as `v0.2.0`.
